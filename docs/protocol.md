# Private protocol

The Linux presentation bridge has a separate strict local method-channel contract,
version 1, described in [native accessibility ownership](native_accessibility_bridge.md).
It carries only revisioned presentation and guarded semantic actions; database
requests and ownership remain in the generated gRPC protocol below.

`protocol/busydata.proto` is generated by protoc 4.36.2, grpc-java 1.84.0 and
Dart protoc_plugin 25.0.0. Frontend/backend release `0.1.0` use strict protocol `15`,
from the shared generated `BUSYDATA_PROTOCOL_VERSION` enum. Other protocol versions are rejected; the package namespace does not imply negotiation.
No reflection, arbitrary Java invocation or legacy negotiation is exposed.

Profile ownership compares all declared values across the Dart/Java boundary.
Ordinary proto3 scalar defaults have implicit presence: Java may omit them even
when Flutter explicitly assigned them. The first-party profile comparator uses
their values while preserving message presence, optional TLS trust/configuration
presence, options, credential bindings and unknown fields. Generated Dart
message equality alone cannot establish this cross-language identity. This
follows the official [protobuf field-presence rules](https://protobuf.dev/programming-guides/field_presence/).
The Java-serialized profile regression covers Open/Adopt admission, and field
coverage guards require explicit handling when Profile, Tls or Ssh gains a field.

Flutter launches the bundled Java executable by absolute path. Its private stdin
pipe receives a fresh 256-bit secret, parent PID and absolute support directory.
One stdout JSON record reports a redacted startup-stage failure, or returns the
allocated loopback port, instance/version and
launch-specific SAN-valid certificate. Captured stderr is discarded, never placed in
the bootstrap stream or forwarded verbatim. The gRPC channel trusts the supplied
certificate only and verifies its hostname; no permissive certificate callback.
Each RPC authenticates `x-busydata-launch`. There is no discovery file or secret
command-line argument. Parent exit or pipe EOF triggers cleanup; startup is
bounded to 30 seconds and Flutter terminates only its specific owned child.

The first-party channel adapter uses public gRPC and HTTP/2 transport APIs with
the official unmodified packages. It records allocated client-stream identities
and validates incoming frame envelopes with at most nine retained header bytes.
Unsolicited response streams and server push terminate the connection with
`PROTOCOL_ERROR`. Late frames on closed lower client streams remain subject to
the official transport's cancellation handling. This validation adds no RPC,
wire negotiation, execution retry or database authorization.
TCP connection and TLS negotiation share a 30-second deadline and retain the
owned physical socket handle until cleanup. Termination cancels an unfinished
handshake immediately. Graceful shutdown cancels pending connection work, waits
for active RPC transport completion, then closes the owned connection. Byte reads
are at most 64KiB; output admission is bounded to 32MiB and preserves transport
backpressure. These transport limits do not increase any RPC message limit.
Real byte-channel failures enter the incoming terminal-error path and close the
physical connection. Normal writer cleanup is separate from RPC completion;
finishing or cancelling a writer never acknowledges a request or a database write.

All requests carry instance/request/protocol identifiers. Session/job/result/
document/plan/value identifiers are opaque and launch-scoped. Stale instance or
protocol requests fail. Execute creates persistent backend state independently of
the RPC lifetime. Duplicate execution identifiers are rejected within the launch;
there is no exactly-once claim across crashes. No application execution retries
or hedging are configured. Cancellation/status use separately admitted RPC slots
(8 control, 24 ordinary, 6 independently reserved language operations and 1 large-command). Background editor
analysis cannot consume the user-command reservation; overflow returns an explicit
resource error rather than retrying a mutation.
An admission rejection supplies `busydata-rpc-rejection: concurrency` with
RESOURCE_EXHAUSTED. Clients classify only this typed reason as busy; an arbitrary
RESOURCE_EXHAUSTED or UNAVAILABLE does not identify an authentication or TLS
failure. Command capacity is released before publication of a terminal reply,
so the acknowledged review can be followed by one execution without a retry.
Capabilities binds an explicit bounded inspection to backend/session/context and
session revision. An independent read-only metadata connection probes catalogs
and instrumentation with five-second statement deadlines; cancellation checks
stop further probes and cleanup releases its reservation. At most 16 entries /
32KiB distinguish available, limited, denied, unsupported, unavailable and
profile-disabled states, with separately checked empty data. No probe grants
permission, executes user SQL, changes the console transaction or caches an
authorization. ConnectionInfo now carries product/version only; the previous
unconditional feature labels were removed when advancing the strict protocol.
Private RuntimeStats reports actual Java runtime and management-reported collector
names alongside aggregate heap/direct/mapped/spool counters. Physical-session
counts describe admitted physical consoles rather than retained uncertain handles;
reserved cancellation and metadata connections have separate bounded ownership.
No diagnostic response contains SQL, values, credentials or process arguments.
The transport admits at most 40 concurrent calls per connection. Ordinary unary
RPCs have a 30-second deadline. CSV/JSON import preview, review and job admission
use the shared five-minute deadline because admission hashes a selected source
of at most 8GiB; preview also verifies that the source stayed unchanged. The
per-call timeout preserves launch authentication metadata. These limits follow
the [gRPC deadline and cancellation contract](https://grpc.io/docs/guides/deadlines/).
Job deadlines include result fetching and remain independent of admission.
Neither deadline expiry nor cancellation retries SQL or a transfer.
History pages are bounded to 100 entries, with 4096-code-point previews and
separate full-SQL chunks up to 65536 UTF-16 units. Imports have bounded preview
rows/bytes and bind review to the selected source SHA256. The server stores the
reviewed digest with the existing single-use, 120-second approval, including when
the caller did not request a preview. Import admission consumes that approval
before its long source check, matches the exact request and session revision,
and verifies the file against the server-owned digest before submitting a job.
Cancellation checks occur before opening and between 64KiB hash reads. Failed or
cancelled admission requires another explicit review. The job rechecks its
captured session revision and verifies its immutable source snapshot before any
database write; the approval is never consumed twice or extended to five minutes.
Retained file exports
validate result ownership and use jobs without requiring a live physical session.
CopySql serializes at most 10,000 retained cells and 1MiB of UTF-8 SQL VALUES text
using the result's source engine. It performs no execution and rejects truncated
previews. Boolean, numeric, binary, temporal and PostgreSQL array representations
remain typed; string escapes do not depend on a guessed session escape mode.
PrivilegeTool inspects bounded principal/direct-grant catalogs or drafts SQL for
an existing exact principal. PostgreSQL role names, MySQL account/role hosts and
MariaDB hostless roles remain distinct. Generation performs no mutation; Flutter
opens an unsaved SQL document and normal Review/Execute enforce approval. Its
typed scope/privilege whitelist rejects unrecognized privileges and code in fields.
Inspection reads no authentication hashes, and reports limited visibility without
claiming complete effective privileges.

Java validates endpoints/options, row/page/message quotas, mappings, absolute
picker paths and review permits. Read-only restrictions supplement application
classification with server/session restrictions. Review tokens are one-use,
120-second fingerprints of operation/parameters/profile/session revision.
Change requests identify their retained source result and, for updates/deletes,
the source row offset. Java verifies finished-result ownership by the same physical
session, a direct single-base-table SELECT, unique verified base-column mappings (display aliases are separate), and exact
retained original values. It rejects views, joins, CTEs, set operations and unsupported
provenance. Parameterized plans revalidate table properties and primary keys before
applying; SQL, parameters, metadata or session changes invalidate approval.

Values distinguish NULL, bool, signed/unsigned integer decimal strings, decimal
strings, IEEE real, UTF-8 text, bytes, JSON, arrays, temporal kind/zone and opaque
engine types. Decimal/integer values never pass through a floating-point proxy.
Temporal display uses the JDBC-reported representation; offset-bearing values
retain offsets, local values are explicitly marked without timezone. PostgreSQL
timestamptz uses OffsetDateTime even when metadata reports TIMESTAMP; Java-time
values use ISO text, and unsupported infinity values retain their engine type. Large cells
have preview/truncation/byte-count/value IDs; full retrieval is byte-addressed.

`ArrayValue` retains its bounded structured children plus one exact PostgreSQL
native representation: `native_literal` or `native_binary`, with the reported
`element_native_type` retained for inspection. These raw forms are mutually
exclusive. Native array lower bounds, nested NULLs, decimals, bytes and engine
representations are not reconstructed from the presentation tree. Binary array
headers, dimensions, element counts and payload lengths are checked before the
pinned driver expands elements; text arrays retain the existing 16Ki-UTF-16
preflight. The binary/parameter ceiling is 1MiB, depth is 16 and element work is
bounded to 1,024, subject to the stricter enclosing row/message quotas.

Reviewed changes bind retained arrays with the central column's verified native
array OID and the pinned driver's public `PgArray` implementation. The driver
must resolve that same array identity. Missing old native evidence, ambiguous
raw forms, changed types, unsupported driver identity resolution or truncated
children fail explicitly. The caller frees each JDBC Array after execution.
For new builtin PostgreSQL assignments, Java accepts a bounded native literal
through `Value.text` or `ArrayValue.native_literal` and reparses its complete
structure against verified native element metadata. It discards any submitted
preview tree and constructs the reviewed typed values itself. The raw literal
and bounds remain exact. Input is limited to 16Ki UTF-16 units, six native
dimensions, 1,024 scalar elements and 1MiB aggregate typed expansion. A validated
native array then uses the same OID-bound parameter path as retained originals.
Native text parameter interpretation requires captured PostgreSQL `array_nulls`
and, for date/timestamp elements, ISO DateStyle. These facts participate in
session-context revisions and are checked before review and again at binding.
Unknown historical datetime-array representation cannot be promoted to current
proof merely by reconnecting; its saved literal must pass pure ISO validation.
Array text is never interpolated into generated mutations. SQL copy preserves
the existing escaped SQL unknown-string contract using the retained literal,
without an inferred type cast; a binary-only array cannot be converted to SQL
text offline and is explicitly unavailable for SQL copy. Its exact retained
transport remains intact.

CSV and TSV serialize arrays from the retained native literal, including explicit
dimension bounds and native escaping. JSON and NDJSON represent that same native
literal as a JSON string, as they do for exact decimal and opaque engine values;
the display tree is not flattened into a JSON list. Binary-only arrays and older
arrays lacking native evidence fail text export without publishing partial
output. An explicit new server-side textual projection is required when native
array text was not retained; exporting an existing result never runs that query.

Editor offsets are UTF-16 code units in original unnormalised SQL (including CRLF).
Responses echo document ID/version/caret and the exact backend, session, context,
metadata snapshot and configuration revisions. Flutter rejects stale bindings.
`CompleteSql`, `DiagnoseSql`, `SqlParameterInformation`, `FormatSql`,
`ResolveSqlSymbol` and `SqlDdlImpact` are independent unary operations; the obsolete
`Analyze` endpoint and `resolve_symbol` field are removed. Each endpoint requires
its matching `AnalysisOperation`. Every operation owns its cancellation lifetime
and a bounded admission slot. Four language CPU tasks are admitted independently
of execution, cancellation and the two general analysis slots.

The lossless tolerant syntax/semantic service consumes a captured central metadata
snapshot. It performs no JDBC work. Completion has deterministic rank, stable
identity, namespace/type/signature detail and UTF-16 replacement spans. Diagnostics
carry code, source, severity, applicability, incomplete evidence and mechanical
fixes. Parameter information returns active argument and signature-aware overloads.
`AnalysisRequest.snippets` admits at most 32 entries, 64 UTF-16 units per name,
4,096 units per template and 32KiB aggregate UTF-8 names/text. Malformed maps
fail explicitly. Snippets enter only syntax-compatible initial-statement
completion contexts, never expression, identifier, string or comment contexts.
Completion replies set `completion_limited` when additional matching items
exceed 200 entries or 256KiB. Parameter information reports `limited` availability
when additional signatures exceed 64 overloads or 64KiB. Returned items are not
silently transformed to fit a cap, and capped sets never claim completeness.
Formatting preserves source tokens/comments/literals and line endings, proves
lexical equivalence and supplies caret mappings; unsafe regions remain unchanged.
`AnalysisRequest.format_current_statement` is transient and valid only for
`FormatSql` with operation `FORMAT`. It chooses the original fragment through
the independent execution splitter's caret/delimiter/whitespace selection rules,
without executing SQL. The reply remains a full-document edit with full-document
token mappings; `no-active-statement` returns no edit. Selection bounds in
`FormatSettings` select an exact token-aligned region when the current-statement
flag is false; omitted bounds format the whole document.
See [sql_language_service.md](sql_language_service.md) for exact dialect coverage.


Hardening adds one-based result ordinals and verified base-column identity separate
from display labels. Staged changes contain changed ordinals; Java obtains
original values from retained rows. Pages return actual first/next offsets and
explicit data/byte-limit/waiting/end/oversized/disposed/failure states. Retained
results have a separately paged catalog and leases independent of job summaries.
`Column.metadata_identity` and `metadata_snapshot_revision` are populated only
from the immutable, proven metadata captured for that execution. Flutter uses
that stable column identity for persistent display preferences. A name tuple or
JDBC display label cannot substitute for absent identity evidence. These fields
do not authorize a later edit or bypass a fresh ownership/provenance check.
PostgreSQL identities use verified native relation/column identity; MySQL uses
verified InnoDB table identity, column epoch and native ordinal. MariaDB's prepared
session witness cannot supply a persistent column identity, so these fields remain
empty and its display preferences are transient.

Analysis echoes the exact document/version/caret/backend/session/context snapshot,
including a session revision advanced after each acknowledged statement (even
while a script continues), completed serialized operations and an explicit catalog
refresh. A committed DDL acknowledgement can schedule independent metadata work
before the remaining script finishes. Each attempt keeps its original physical,
context, configuration and publication fences; a later real statement or cleanup
boundary may admit unreconciled effects again. Java validates ownership before
and after metadata and analysis;
Flutter invalidates it when operations begin or refreshed session replies arrive.
Formatting returns lossless lexer token positions in both original and formatted
UTF-16 coordinates. Flutter maps every selection/caret through those positions in
one undo operation and rechecks the captured target after native confirmation.
`ResolveSqlSymbol` resolves the active statement's syntax-identified relation or
alias from that same captured metadata snapshot. It does not fetch catalogs or
source. Literals/comments, virtual scopes, ambiguous aliases and preceding
unresolved context changes cannot select a persistent object. Replies include
exact owner/namespace identities and distinguish unavailable, limited and absent.
Job summaries have a revision-bound 32-entry/1MiB paged catalog. Verified columns
come from the independent retained-result catalog, rather than duplicated summaries.
Normal requests are capped before protobuf decoding at 64KiB, staged recovery at
1MiB, all six language requests at 1MiB, and explicitly admitted execution SQL/
schema-snapshot operations at 16MiB. The language budget accommodates the maximum
262,144 UTF-16 document units in worst-case UTF-8 plus bounded snippets/settings;
it does not inherit execution's much larger payload allocation. Inspection
settings admit at most 64 entries with 128-unit codes and 16-unit severities.

Live session replies expose current catalog, schema, search path and context
revision. Formatting/completion require the same snapshot before applying edits.
Schema plans expose complete/equivalent flags, dependency impacts and unsupported
differences. The native designer binds generation to captured metadata.

`EXPORT_QUERY` explicitly submits one reviewed read execution directly to a file;
`EXPORT_RESULT` exports only existing retained data. Transfer requests bind source
hash, mapping, encoding, delimiter, NULL contract, transaction policy and resource
options. Job replies separate processed, committed and rejected row counts.
SSH trust review binds profile, exact endpoint, algorithm and fingerprint; opaque
machine-local trust references are stored only by Java. No trust probe offers
passwords or keys. Changed keys require an explicit replacement review.

`ReviewAuthentication` / `Authentication` carry exact engine principals and an
optional entered password. Approval binds the password, operation, server policy
and physical-session revision, but display/history contain only a redacted command.
SQL tabs are not used for password management. No automatic mutation retries occur.

`EditDraft` lists/saves/rebinds/deletes Java-owned verified staged recovery. Its
save operation validates the same editable source and original rows as ChangePlanner.
Only Java constructs StoredEditDraft; clients cannot submit stored row proof.
Rebinding returns retained rows plus changed ordinals for a new explicit console;
it executes no source SQL. `recovery_id` binds application to the exact saved
intentions, and durable state prevents replay of committed/uncertain batches.

`StoredEditDraft.source_time_zone` (optional field 10) and
`source_system_time_zone` (optional field 11) retain native
MySQL/MariaDB timestamp interpretation facts. Presence is required for a saved
TIMESTAMP projection: absent historical facts remain explicitly unavailable,
with the saved rows and assignments intact. Live session context captures these
facts independently of SQL mode and advances its context revision when they
change. Retained physical metadata proof also carries a fixed-offset key, so a
timezone change cannot authorize a wall-clock original against another instant.
These optional facts do not create another storage format or fabricate values
for existing payloads. Typed assignment conversion was introduced in user-data
schema 3 and runs in the schema-4 initialization transaction when still needed;
absent historical timezone facts remain absent.

`RuntimeStats` exposes only aggregate JVM heap/direct/mapped storage and owned
session/job counts for acceptance. It carries no SQL, result payload or arbitrary
JMX/method invocation. Release measurements also sample both actual process RSS.

Transaction-command replies identify the exact acknowledged COMMIT/ROLLBACK. A later context/cleanup failure can quarantine the physical session while retaining that acknowledgement and a separate warning. It must not relabel an acknowledged commit as cancelled or unknown. Reviews use the live lexical SQL mode and session revision; queued intervening work invalidates approvals.

Retained editable sources store their original lexical settings separately from current session context. Java staged recovery includes the complete captured original SQL mode, including modes not interpreted by the language service, and the standard-conforming-strings flag. Quoting flags alone cannot reconstruct expression precedence, concatenation or unsigned-subtraction behavior. A recovery record with unknown original quoting remains preserved but cannot authorize ambiguous edits. Native role tools include an explicit MySQL/MariaDB DEFAULT_ROLE scope; generated SQL still enters normal Review/Execute. Native view migration snapshots include ownership, security/options/check behavior and visible grants, with explicit unsupported visibility instead of silently discarding properties.

The release wire contract is strictly version 15, generated from
`ProtocolVersion.BUSYDATA_PROTOCOL_VERSION` in the shared schema. Bootstrap and
every request use that same value; all other versions are rejected. There is no legacy negotiation. The protobuf package name is a code
namespace, not a negotiated compatibility promise.

Ordinary `Explore` enumeration defaults to 128 objects and accepts at most 500.
Native keyset queries fetch one additional object to distinguish a complete page
from a continuation. Pages target 512KiB, retain the 1MiB reply ceiling,
and reject oversized native identities. Signed opaque continuations bind the
backend owner, source, session/context revisions, kind, database, schema, parent,
name filter, exact-name/overload and routine subtype filters, and catalog fingerprint. Refresh starts a new enumeration; stale,
cross-scope, changed-catalog and foreign-backend continuations are rejected.
Scoped count aggregates report `AUTHORITATIVE_TOTAL` with `total_count`, including
known zero. Absence of a count remains `COUNT_UNAVAILABLE`; a first page is never
implicitly a total. Compound indexes and foreign keys enumerate once per native
object. Counts concern metadata objects, never table data rows.

`SchemaObjects` echoes source/session/instance and requested scope. Requests may
require an acknowledged session/context revision. `SchemaObject.subtype`
distinguishes PostgreSQL ordinary, partitioned and foreign tables, regular and
materialized views, sequences and function/procedure routines. MariaDB sequences
are separate from ordinary tables; MySQL sequence enumeration is unsupported.
Minimal routine enumeration retains overload identity without fetching bodies.
Function/procedure group requests carry a validated routine `subtype`, echoed in
the reply; their counts and continuations apply only to that subtype.
`ExploreRequest.subtype` is a routine-only filter. Relation lookups leave it
unspecified and verify the native subtype and stable identity returned in
`SchemaObject`; a returned relation descriptor is never copied into that filter.
`default_namespace` names the default in the actual targeted physical database,
including when it falls outside the current discovery page. Exact bounded
namespace lookup can retrieve that real object without assuming it was loaded.
Rejected continuations return FAILED_PRECONDITION with the allowlisted
`busydata-metadata-reason: restart-enumeration` trailer; the client presents a
scoped stale/retry state. Timeouts and cancellations retain distinct statuses.
Global Object Search remains a separate bounded query and continuation contract.
`availability=available` describes a usable page, not completion. Enumeration
consumers must follow `complete`/`continuation` within their surface budgets or
provide bounded page navigation. Exact child requests retain kind, parent, name
and native identifier; clients verify the echoed scope before adoption. Transport
name ordering does not replace native column ordinal ordering in positional UIs.

`OBJECT_DEFINITION` acquires one exact database/schema/kind/name/overload target
on a read-only metadata view and returns `inspected_object`, definition provenance
and completeness. It does not return or capture a whole-schema snapshot. Native
definitions use supported SHOW CREATE or PostgreSQL catalog functions; generated
PostgreSQL table/view/sequence definitions explicitly identify omitted ownership,
grants and options. Definition output is limited to 64KiB. PostgreSQL sequence
inspection reads pg_sequences, omits unknown last_value, and never calls nextval.
Unsupported native partitioned/foreign-table DDL is reported as unavailable.
Designer inspection and reviewed schema snapshots retain their separate evidence
and mutation approval paths.
`CAPTURE_SCHEMA` with a nonempty `table` captures that exact ordinary table only,
under the supplied `catalog`/`schema`, and returns its `inspected_object` identity.
Missing/inaccessible or unsupported relation kinds fail instead of substituting a
whole-schema snapshot. Scoped comparisons retain the same snapshot version,
engine/schema matching and reviewed migration constraints as schema comparison.

Schema artifacts export format 2 with exact constraint name/type records. A
bounded one-way format-1 import precedes the format-2 comparison core; it never
rewrites an imported file or introduces a legacy wire path. Duplicate decoded
JSON keys, malformed Unicode, trailing roots, and the complete JSON node budget
are validated before model construction. Exact child constraint requests carry
the native type in `identifier` when names are not unique. See
[schema artifact ownership](schema_artifacts.md).

`Explore.independent_metadata` requests a read-only ephemeral view even for the
owning connection's current database. Explorer tree enumeration always sets this
flag so a slow catalog read cannot own the physical session's disconnect lock.
Execution-owned metadata still supports live session-local objects through its
existing path. A disconnected source cannot publish a successful metadata reply.

A PostgreSQL metadata view for another database opens an ephemeral read-only
connection at that database using the owning credentials, TLS policy and SSH
forward. Its errors and cleanup belong to that view. It does not switch the
console database or borrow the console transaction. New dedicated query/table
sessions can likewise specify their database at physical connection creation;
the saved profile remains unchanged. The adapter still rejects changing a live
PostgreSQL connection to another database. Metadata admission remains two views,
ordinary physical session ownership remains eight. Explorer projects the central
immutable metadata snapshot; no serialized response cache supplies authority.
Its resident/persistent bounds, publication and stale restoration rules are in
[metadata_platform.md](metadata_platform.md).

The captured metadata snapshot revision also identifies its immutable
physical-session resolution view. An opaque execution or changed exact native
observation invalidates that view without changing the durable configuration
revision. Existing session/context and snapshot ownership fields fence language,
Explorer, browsing and retained provenance responses; a durable refresh revision
cannot substitute for an unknown session-local resolution epoch. The epoch and
native observations remain Java-owned internal evidence, never client assertions.

Reviewed native restores also fence persistent-source acquisition, publication
and retained proof admission. These internal mutation and proof epochs cannot be
supplied or overridden by a client. Existing stale/unavailable responses preserve
retained result identity and draft ownership; an old proof cannot become editable
through a later refresh. Acknowledged restore reconciliation advances metadata
revisions independently of the console transaction. Unknown outcomes keep their
job state and require explicit metadata reconciliation, without execution replay.


The current contract includes explicit generated table browsing (reviewed identifiers and bound
values), a disk-backed retained-view mapping with fixed fetched-row snapshots,
non-mutating editability evidence using ChangePlanner verification, bounded
snapshot difference presentation, and verified connection-test endpoint details.
Page `source_rows` maps every view position to the original retained row. Copy,
value reads, leases and retained export resolve that mapping without database SQL.
The source result and view share spool quota; filters do not mutate source rows.
There is no protocol negotiation or old-peer fallback.

Workbench metadata, language and retained-result operations use the typed
`busydata-workbench-reason` gRPC trailer for actionable failures. The allowlist
is `unsupported`, `unavailable`, `denied`, `stale`, `cancelled`, `timed_out`,
`incomplete_metadata`, `invalid_owner`, `invalid_revision`, `malformed_request`,
`result_disposed`, `value_truncated`, `row_no_longer_current`,
`transaction_unknown`, `backend_restarted`, `read_only_policy`, `session_busy`,
`edit_identity_required`, `edit_columns_read_only`, `edit_result_not_ready` and
`edit_projection_unsupported`. Java's `WorkbenchFailure` maps
these codes to fixed status categories and a safe description without accepting
SQL, values or arbitrary exception text. Flutter accepts a reason only when the
exact allowlisted trailer and its expected status agree; missing, unknown or
contradictory trailers stay unclassified. A transport UNAVAILABLE alone cannot
prove a restarted backend or an unknown transaction outcome. Human-readable
messages are not parsed into these causes. Recoverable errors retain the
captured owner and draft; no reason authorizes replay or automatic mutation retry.
When an admitted job fails with a `WorkbenchFailure`, `JobInfo.error_code`
contains the same exact allowlisted wire reason. It remains distinct from
SQLSTATE, filesystem and native-client error codes. Table documents and Jobs
localize recognized reasons without parsing messages; unknown job codes do not
acquire an inferred cause. A queued browse rechecks its accepted metadata owner
before preparing or executing its SELECT, and a stale job never retries the query.

`DescribeConnection` returns the authoritative generated JDBC address and bundled
driver identity. Typed TLS policy distinguishes `DRIVER_DEFAULT`, explicit Disabled,
Require, Verify CA and Full Verification; trust sources and the TLS-key password
are profile-scoped. `TestSshConnection` carries only the profile/SSH identity and
secrets, never database/TLS fields. It authenticates SSH without opening JDBC or
requesting a database forward. The main `TestConnection` tests the full connection.


## Central metadata and result editor contracts

`SchemaObject` adds stable, quoted, normalized and parent identities, snapshot and
source revisions, introspection level and state. `SchemaObjects` echoes snapshot
and configuration revisions. Explorer pages project an atomically published
normalized model; they are not authoritative serialized response caches.
`MetadataSettings` reads or atomically saves a revision-bound policy and performs
explicit full/incremental refresh. It caps requests at128KiB and status pages
at128 scopes, bound to one metadata snapshot. Names/structure/source are distinct
levels; denied, stale and incomplete scopes do not prove absence.
The existing `cache_state` status distinguishes `REBUILT_VERSION` from
`REBUILT_CORRUPT` and unavailable/current/partial catalog states. `WRITE_PENDING`
means a published in-memory snapshot is awaiting its bounded cache write;
`WRITE_UNAVAILABLE` means that write failed. Neither state revokes the snapshot's
separate coverage evidence. The UI localizes these states and preserves unsaved
configuration fields. No cache failure authorizes replay of SQL or mutations.
Rebuildable
metadata cache format 5 stores bounded native identifier evidence with normalized
objects and invalidates older acquisition semantics before loading objects or
fingerprints. The cache migration is independent of the strict wire version;
user-data schema 4 retains profiles, introspection configuration and edit drafts.
`SessionInfo.metadata_source_identity` is the opaque ID resolved and captured at
physical acquisition. Independent metadata connections inherit that ID. Clients
must not derive it by serializing profile messages. The one-way schema-4 source
binding migration preserves existing opaque object/column identities; it changes
no wire fields or strict protocol version.

`ValueAssignment` separates value, SQL NULL and DEFAULT; no assignment means unset.
`StagedChange.values` moved to field5; oldfields2/3 are reserved. Reviewed values
carry the same intents, while retained originals remain exact Values. Only Java
turns DEFAULT into generated SQL grammar. SQLite user-data schema3 atomically
migrates schema2 stored assignment maps once; no legacy runtime wire path remains.

`ResultAggregate` calculates explicit retained result/view row ranges and ordinals
with100000cells/8MiB/2s bounds. It preserves exact decimals, reports repeating
averages as exact ratios and declares partial snapshot scope. Unsupported or mixed
ordering remains explicit. `CloneRow` returns a staged INSERT omitting generated
and identity/key columns. `RelatedRows` binds exact FK metadata, retained source
row and values; NULL key components disable navigation. Returned BrowseRequests
include metadata and origin proof. Review and submission validate that proof,
quote verified identifiers and bind values through the ordinary browse pipeline.
Ordinary BrowseRequests require a nonempty canonical metadata object identity,
a positive snapshot revision, and the exact server-selected catalog/schema/name.
Missing or half-populated selection proof fails before native metadata reads.
The selected TABLE or VIEW and its columns must have complete structural evidence.
Flutter's logical document key and restored name hint are not selection proof.
An explicit user action resolves/enriches the selected relation and its column
scope before constructing the request; a bounded one-column transport page is
only an acquisition acknowledgement, never complete enumeration evidence.
The final exact relation projection must belong to that same snapshot/configuration
and original backend/profile/physical/session/context owner. RelatedRows retains
its backend-issued target and origin proof without frontend rebinding.

Browse preparation binds every acquired column page and typed predicate to one
accepted metadata source generation/configuration/revision and physical
session/context owner. Metadata acquisition releases the outer physical lock and
rechecks the original owner when reacquiring it; callers cannot pre-hold that lock.
Acquisition may publish new metadata, but cannot upgrade a request carrying an
older explicit revision. Related-key verification uses that same accepted model;
approval fingerprints use its captured scalars rather than a newer recapture.
Submission consumes its single-use approval before job admission and checks the
accepted owner again on the physical worker before issuing SQL. A stale owner
requires a fresh explicit review; SQL and actions are never retried automatically.

`Editability.reason_code` carries the allowlisted cause of a noneditable
assessment, with an empty human-readable `reason`. Read-only policy, unknown
transaction and a busy session are checked before retained-result validation;
these fast denials do not prove result ownership. A foreign physical result
returns `invalid_owner`; a wrong requested table/scope or malformed retained
ordinal returns `malformed_request`. These checks still precede retained proof,
parsing and native metadata acquisition, so a forged target cannot disclose a
private denied/stale/cancelled proof. Unknown/expression/multirelation or repeated
base-column projections and unsupported direct-SELECT shapes return
`edit_projection_unsupported`; unfinished results return `edit_result_not_ready`.
Verified metadata that lacks a complete projected primary/nonnullable unique key
returns `edit_identity_required`. A projection containing only generated/read-only
columns returns `edit_columns_read_only`. No negative reason permits editing.

Typed disposed-result, metadata-limit and value-validation failures retain their
existing reason classifications before generic argument handling. Cancellation,
parser admission refusal and known typed parser timeout are not relabeled as
unsupported SQL. Unclassified local assessment failures return `unavailable`
without exception text or an inferred permission cause. SQL/RPC failures keep the
existing typed trailer/status mapping. Flutter retains only a matching typed
reason under its current request/model/backend/result-owner fence; unknown,
missing or mismatched trailers remain generic. It localizes the code through all
configured catalogs, never parses an English description, and keeps editing
disabled on a current failure. Failure classification itself never replays SQL
or resubmits the failed assessment. A genuinely new, replaced or completed result
lifecycle may request a fresh assessment under the same owner checks; the user
may also explicitly request one.

## Metadata response ownership

Strict protocol 15 adds the shared Java-issued metadata source identity to
`SessionInfo`, `SchemaObjects`, `Analysis`, `MetadataSettingsReply` and
`RelatedRowsReply`. Related-row replies also carry their actual backend, profile,
physical session, session/context revisions and metadata configuration revision;
the snapshot revision remains explicit. `RelatedRowsRequest` requires presence
of both expected session and context revisions, including legitimate zero.
Java checks those revisions under the physical-session lock before retained-row
or catalog access. Missing, negative, forged and stale owners fail explicitly.

Connected replies use the actual captured source/configuration even when contents
are unavailable. Stateless/disconnected analysis has no metadata authority.
Settings projection requires one matching immutable policy/snapshot pair and
revalidates its owner before response publication. The Java source identity uses
the central data-source identity, including the visibility principal; Flutter
neither derives it from labels nor hashes connection settings independently.
Every SessionInfo acknowledgement, including disconnect, retains its exact owner.

Related-row responses admit at most 128 relationships and 512KiB including the
stamped protobuf envelope and message framing. If either bound is exceeded, the
response removes all choices and reports an explicit relationship limit. It
never presents a silently truncated list as complete. Cancellation is checked
while enumerating each verified relationship. Existing per-key and typed-value
bounds still apply.

The shared scalar frontend ownership registry and valid revision-domain changes
are described in [metadata revision ownership](metadata_revision_ownership.md).
Old protocol-14 clients/backends fail the existing strict version check. There is
no negotiation or parallel wire path. This change requires regenerated Java and
Dart sources and no persistent user-data or metadata-cache migration.
